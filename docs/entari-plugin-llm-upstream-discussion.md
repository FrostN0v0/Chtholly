# entari-plugin-llm 上游候选项讨论清单

更新日期：2026-10-23。

本文件记录本轮讨论状态，便于逐项决定纳入、收窄、暂缓或排除。候选不等于已批准实现；接口名称、默认值和具体实现尚未约定时，不视为最终设计。

上游现状以 `entari-plugin-llm 0.4.0` 固定提交 `c9c8f168cac60ae8a8a5962bc8c43fe7bcbacc1d` 为核对基线，不将 Chtholly 旧版兼容补丁直接当作新版缺陷。

## 已讨论的候选边界

### 3. 关闭默认自动聊天

- 允许其他插件只使用模型服务和工具能力，不由上游自动接管普通寻址消息。
- 关闭自动聊天不等于关闭模型服务、配置重载或显式管理命令。
- 具体配置名、热切换和在途任务行为仍需确定。

### 4. 调用方注入运行上下文

- 调用方指开发者或插件，不是聊天中的终端用户。
- 可以提供当前 Session、账号、事件及工具执行需要的依赖。
- 这些对象用于执行和依赖注入，不自动变成提示词或供应商请求参数。
- 先开放现有执行链需要的入口，不先设计包含所有业务状态的巨大上下文对象。

### 5. 调用方控制本次生成的工具集

- 支持默认工具集、指定工具子集和完全禁用工具。
- 由调用方决定是否按会话持续使用同一策略，底层不强制新增持久化权限系统。
- 限制同时作用于模型看到的声明和实际可执行入口，不能只隐藏声明。
- 选择工具不替代工具自身对用户、频道和资源的权限检查。

### 6. 工具声明是否允许并发

已纳入考虑的方向：由开发者在工具定义中声明是否允许并发，执行器据此调度。

- 模型决定调用哪些工具、是否分轮等待结果；不能覆盖宿主规定的执行限制。
- 同一批中的工具数组有顺序，不等于协议自动承诺依序执行。
- 串行执行同一批调用，不会让模型在两次执行之间看到结果并修改后一项参数；这种数据依赖仍需分轮。
- 不是将一个会话永久设置为全部串行或全部并行。
- 不在上游硬编码 Chtholly 的工具名称分类名单。

尚需讨论：

- 是否采用 shared/exclusive 一类语义，以及未知工具的默认值。
- 独占工具是否作为前后批次的等待边界。
- 是否允许根据经过校验的本次参数决定执行属性。
- 并发上限和取消、停止行为。
- Entari 外部工具与 Agno Toolkit 是不同执行路径，必须明确各自覆盖范围，不能只改前者就宣称所有工具都受控。

## 第二批：剩余待讨论项

### 7. 整次生成的工具调用总上限

**解决的问题**

模型反复调用工具，导致任务长时间不结束。现有按插件或 Toolkit 的限额，不等于整次生成的统一总限额。

**候选改动**

- 一次 `generate()` 共用一个工具调用计数。
- 暂停、执行工具、继续生成时不重置。
- 达到上限后有明确的结束行为，避免无限返回超限错误又继续请求模型。

**边界与待讨论点**

- 不负责多次独立 `generate()` 之间的业务额度。
- 不照搬 Chtholly 的固定数值。
- 明确覆盖哪些工具，以及失败、拒绝、未执行调用怎样计数。
- 先判断现有分组额度能否满足使用需求，再决定是否新增总额度。
- 当前 `$call_limit` 的实际语义见文末附录。

### 8. 参数校验与安全错误结果

建议拆为两个可独立讨论的小修复。

#### 8.1 参数进入执行上下文前先检查

**解决的问题：**模型参数直接合并进工具执行上下文，可能包含未知字段、缺少必填字段，或干扰宿主注入字段。

**候选改动：**按真实工具声明检查参数；模型只提供业务参数，不能覆盖 Session 等宿主依赖；错误返回模型纠正，不启动有问题的工具调用。

**边界：**复用已有声明和校验能力，不维护第二份 schema，不自行实现 JSON Schema 引擎。

#### 8.2 不将内部异常原样返回给模型

**解决的问题：**异常文本可能包含凭证、内部地址或文件路径。

**候选改动：**可公开的参数或业务错误保留纠正信息；内部异常返回受控信息，保留安全诊断途径；明确标记失败，不包装成成功结果。

**边界：**不靠少数正则宣称完全脱敏，也不把所有错误都隐藏成同一句执行失败。

### 9. 停止、取消与剩余调用结算

**解决的问题**

工具要求结束后，同批后续调用可能仍然执行；取消后的任务清理和结果状态也需要明确。

**候选改动**

- 收到停止要求后，不再启动尚未执行的调用。
- 取消时通知并等待已启动任务清理。
- 区分成功、失败、未执行和结果未知。
- 保留调用 ID 与对应结果，避免残缺的工具记录。

**边界**

- 已发生的外部操作无法自动撤回。
- 结果未知的发送或写入不自动重试。
- 不新增审计数据库，不承诺跨崩溃的 exactly-once。
- 与第 6 项一起确定：串并行策略会影响停止后还能阻止哪些调用。

### 10. 终止原因与自动收尾

#### 10.1 暴露明确的终止原因

调用方可以区分正常完成、工具要求停止、工具额度耗尽、取消和执行失败。

优先复用 Agno 已有状态，只补执行器确知的信息，不另造庞大状态机。

#### 10.2 自动无工具收尾

候选能力：工具额度耗尽后，再请求一次模型，根据已有结果生成总结。

此前建议暂缓，尚未形成用户最终决定：它会增加费用，也可能重复已发送内容。第 5 项支持禁用工具后，调用方可以自行决定是否追加纯文本生成。

### 11. 模型与工具执行观察接口

**解决的问题**

调用方希望记录耗时、状态、用量和执行过程，却需要修改私有方法或包装底层客户端。

**候选改动**

- 先核对并接通已经声明的 hooks。
- 再补缺失的模型调用、工具开始、完成、失败和取消事件。
- 调用方接收事件，自行实现日志或管理界面。

**边界与待核对点**

- 不移植 Chtholly 的数据库、WebUI 或完整审计系统。
- 模型步骤事件不等于真实 HTTP 请求，也不保证能观察供应商 SDK 的每次重试。
- 观察回调失败不能触发工具重复执行；权限检查不能依赖可忽略的日志回调。
- 注册接口接受 `pre_hook/post_hook/tool_hooks`，不代表外部工具执行路径已经实际执行这些 hooks，需核对真实行为。

### 12. 多模态结果传递

#### 12.1 模型生成图片后，调用方能正常取得

- Agno 修复对应 provider 的图片解析与传播。
- plugin-llm 在公共响应接口中暴露媒体结果，不要求读取私有 `_run_output`。
- 已核对的丢图路径不代表所有 provider 都有相同问题。

#### 12.2 工具返回图片后，模型能继续看到

- 尽量复用 Agno 的 `ToolResult` 媒体结构。
- 不把媒体结果简单转换成字符串。
- 暂停继续后，图片必须真正进入下一次模型请求。

**边界**

- 不搬入 Chtholly 的 `media_ref` 管理、收藏、发送和来源授权策略。
- 不自动发送模型生成的图片。
- Agno 外部执行结果接口若不足，需要配套修改，不能只改 serializer 就宣称完成。

## 附录：现有 `$call_limit` 到底限制什么

### 计数范围

不是每个工具函数各自得到一个上限，而是一个配置中的工具插件或 Toolkit 共用一个计数器。

- **Entari 插件：**按注册工具的插件 ID 找到对应 guard。同一 guard 下的函数共同消耗额度，不自动给每个函数单独计数，也不能假定父插件额度会递归覆盖所有子插件。
- **Agno Toolkit：**同一个已配置 Toolkit 实例中的函数，共用一个 guard；guard 接在函数的 pre-hook 上。
- **作用时间：**原生 `_run_agent()` 开始时创建工具和计数器；同次运行的暂停、继续共用它们；下一次独立生成重新创建计数器。
- **不是：**每日配额、整个会话的终身额度、请求频率限制或并发数量限制。

### 举例

假设一个实际存在的插件 `my_tools` 提供 `search` 和 `read_page`，配置如下。插件名仅用于示意，不是要求安装的新依赖。

```yaml
entari_plugin_llm:
  tools:
    my_tools:
      $call_limit: 3
```

同一次生成中：

| 调用 | 是否放行 | 共享计数 |
| --- | --- | --- |
| 第一次 `search` | 放行 | 1 |
| 第二次 `search` | 放行 | 2 |
| 第一次 `read_page` | 放行 | 3 |
| 再调用任意一个函数 | 拒绝 | 已用尽 |

另一个插件或 Toolkit 有自己的计数器，不受这一组耗尽影响。下一次独立生成中，这一组额度重新开始。

### 边界行为

- 不配置 `$call_limit` 时，这一层不限制该组；这不代表整个运行没有其他限制。
- 当前校验允许非负整数：`0` 表示该 guard 不放行任何调用，并不等于隐藏或卸载工具。
- 计数发生在执行前的 guard 放行时，不是成功后；后续执行失败不退还额度。
- 超限抛出工具执行异常。外部执行器会把它交回模型作为错误，不能理解成整次 Agent 自动终止。
- 只有实际挂载对应 guard 的工具受此配置限制；不能将它当作覆盖 Skills 等所有来源工具的统一全局预算。
- 因此第 7 项若保留，新增的价值应是整个生成的统一额度与终止语义，而不是重复实现现有分组计数。
