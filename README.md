## 🛠️ 快速开始

当前支持 **Python 3.11**，使用 [uv](https://docs.astral.sh/uv/) 按 `.python-version` 和锁文件安装，不复用其他 Python 版本的虚拟环境。Entari 0.19.0 已移除 Python 3.10 支持，本项目不再保留 3.10 兼容路径。

```shell
git clone https://github.com/FrostN0v0/Chtholly.git
cd Chtholly
uv sync --locked --all-extras
uv run --locked main.py --check
uv run --locked main.py
```

默认 `entari.yml` 是不需要账号或模型凭证的最小配置：初始化 SQLite，启动只监听 `127.0.0.1:8120` 的 Satori 服务。不自动连接 QQ、不加载 LLM、浏览器、TTS、WebUI 或工坊；没有配置协议端时，服务正常运行，但尚不能收发 QQ 消息。首次启动会建立数据库父目录，不需要复制别人的 `data/`。

### 接入自己的账号和功能

保留 `entari.yml` 作为受版本管理的默认配置；个人配置放在不入库的 `entari.local.yml`，凭证放在 `.env`。可先复制最小配置，或参考 `entari.full.example.yml` 挑选需要的插件段。完整示例不是免配置套餐：启用哪些功能，就需要提供对应账号、模型和服务；删除不使用的插件与适配器段，不要填写假的凭证来绕过检查。

```shell
uv run python -c "from pathlib import Path; Path('entari.local.yml').open('xb').write(Path('entari.yml').read_bytes()); Path('.env').open('xb').write(Path('.env.example').read_bytes())"
```

上述命令拒绝覆盖已有文件；只用于没有个人配置的新安装。配置选择顺序为 `--config PATH`、`ENTARI_CONFIG_FILE`、`entari.local.yml`、`entari.yml`。也可用 `--config entari.yml` 显式检查最小配置。

- **OneBot**：在 `server.adapters` 中加入完整示例的 `@onebot11.reverse` 段，填写 `.env` 的 `ONEBOT_TOKEN`，并在 LLBot 等协议端配置同一个 token；反向 WebSocket 地址为 `ws://127.0.0.1:8120/onebot/v11/ws`。
- **LLM / WebUI**：选择自己确实可用的模型、接口和密钥；启用工坊必须先设置明确的 `WEBUI_PASSWORD`。OneBot 用户不需要同时启用官方 QQ 适配器。
- **官方 QQ**：单独配置 `QQ_APP_ID` 和 `QQ_APP_SECRET`，它们与 OneBot token 无关。
- **TTS / 工坊 / 网页作品**：还需要相应的外部服务。工坊隔离验收要求 Linux 主机环境和预构建 Linux Docker 镜像，原生 Windows 上运行 Bot 不等于支持工坊验收；SSO、受管重启和作品服务器不是普通首启的必装项。

启用浏览器或 LLM 后，先显式准备所选功能的资源，再检查和启动：

```shell
uv run --locked main.py --prepare
uv run --locked main.py --check
uv run --locked main.py
```

`--check` 不下载、不建目录、不连接账号或模型；`--prepare` 建立所需目录、准备匹配锁定版本的 Chromium 与 tokenizer，不启动 Bot 或调用模型。普通启动不再偷偷下载这些资源，缺失时会提示准备命令。Linux 若缺浏览器系统库，可显式使用 `--prepare --with-browser-deps`；该操作需要系统包管理器权限，不会自动执行 `sudo`。默认最小配置无需浏览器或 tokenizer 下载。

LLM 的价格元数据默认使用随包副本。只有显式设置进程环境 `LITELLM_LOCAL_MODEL_COST_MAP=false` 才恢复上游导入时联网更新；这不是普通启动的必要步骤。

### 更新已有安装

升级前停止 Bot、备份个人配置及数据库；若以前直接修改 `entari.yml`，先保存为 `entari.local.yml`，避免拉取时覆盖个人设置。不要用删除数据库或覆盖 `.env` 的方式解决升级报错。

```shell
git pull --ff-only
uv sync --locked --python 3.11 --all-extras
uv run --locked main.py --check
```

检查提示配置迁移时，按对应迁移说明操作；提示缺少资源时运行 `--prepare`，检查通过后再启动。仅 `git pull` 后直接用旧虚拟环境运行，不会自动完成依赖和配置升级。

`uv.lock` 固定兼容组合：Entari `0.19.2+chtholly.2`、WebUI `1.1.1+chtholly.1`、Server `0.8.0+chtholly.1`、Permission `0.2.0+chtholly.1`、Database `0.4.2`、HTMLRender `0.1.0+chtholly.1` 与基于原 Git 提交的 LLM `0.2.2+chtholly.3`。补丁制品随仓库提供；`python scripts/build_patched_wheel.py --package entari`（或 `webui`、`server`、`permission`、`htmlrender`、`llm`）按固定来源与 SHA-256 重建，不手改 `.venv`。LLM 保留原工具桥及已验证的 Agno / LiteLLM 组合。干净环境验证入口为 `uv run --locked python scripts/smoke_startup.py --resources`；CI 使用 Python 3.11，分别覆盖 Windows/Linux 首启及 Linux 完整资源路径。

### Entari 0.19.2 / WebUI 1.1.1 升级边界

- [Entari 0.19.2](https://github.com/ArcletProject/Entari/releases/tag/v0.19.2) 提供原生 `ConfigModify` / `ApplyReport` 配置应用器；[WebUI 1.1.1](https://github.com/ArcletProject/entari-plugin-webui/releases/tag/v1.1.1) 采用字段级差异保存，不把新默认值写入文件，恢复默认值会删除对应字段，尽量保留注释、顺序、列表元素与环境引用。
- 新增独立插件管理页，区分禁用与卸载，展示子插件及无 metadata 的插件，并支持配置、启停、重载和卸载。配置与 Schema 归属使用原生实现；受保护的内建插件仍遵守上游限制，工坊插件不能绕过其专属工具管理。
- 两个原生配置 PUT 接口要求 `If-Match`：缺失返回 428，过期返回 409；请求按整段替换，未提交字段会删除。响应保留原生 `apply`、最新 `data` 和 `etag`，旧客户端不能继续依赖隐式合并。公网部署须同步 `scripts/webui.Caddyfile` 的内建插件列表与精确生命周期路由，不开放整个后端 API。
- 不能只裸换官方 WebUI wheel：保留同 Cookie 多连接隔离、独立清理、认证初始化失败重试及布尔/数字差异补丁。认证修复从固定上游源码构建，所需 Node.js / npm 为 `24.15.0` / `11.12.1`；不改压缩后的业务脚本。
- 保留仍未被上游覆盖的命令解析器回滚、Schema 片段代际隔离、Service 对象清理、import 别名重绑定及子树替换补丁。原生 `plugin.niche`、函数热替换、指纹与 API Hook 已有使用，不为升级新增第二套运行边界。
- LLM 工具声明绑定同一注册代际，跨暂停与纠正继续复用；暂存候选未提升时不接管旧工具，替换后拒绝旧轮次调用，不能把旧参数交给新一代同名 handler。外部工具纳入原生订阅者任务管理，卸载会取消并等待在途调用，阻止晚到副作用；继续使用原生 Function/schema、Session 注入及真实工具暂停/继续。
- 数据库 Ready 处理器使用原生 `on_stage("blocking")` 注入，在表准备完成后继续迁移与用户同步；保持原优先级，不改为可能早于建表完成的默认 `prepared` 阶段。
- 保留生产 Satori 共享服务修复：锁定 `satori-python` `1.3.9.post1+chtholly.1` 与 `satori-python-server` `1.3.7+chtholly.1`，避免单个适配器结束导致 WebUI/HTTP 一同退出。两制品均进入工坊镜像，可分别用构建器的 `--package satori`、`--package satori-server` 重建；`vendor/satori/*.whl` 在 Git 中显式按二进制保存，禁止行尾转换。
- Server `0.8.0` 新增适配器配置 Schema；本地补丁保留 QQ WebSocket/Webhook 和 OneBot 的类型校验，修正独立 WebUI 与整份配置之间的嵌套引用，并支持官方适配器的 `PathLike` 字段。Permission `0.2.0` 在加载权限状态前等待原生数据库迁移；仅从官方 wheel 元数据补回漏打包的 README，不修改权限算法。两项新制品同时进入工坊构建输入。
- 框架版本变化后，工坊需用 `scripts/build_workshop_sandbox.py` 重建匹配的 Python 3.11 镜像并重新验收；旧框架镜像及报告不能用于新激活。此升级不更改个人配置、数据库或已发生的消息交付。

## WebUI 外观与配置应用

管理页保留 Entari Logo 原色，使用中文、中性色卡片和语义状态色，支持深浅色与窄屏布局。会话页默认展示格式化正文、引用和实际回复；系统指令、工具记录在实色弹窗中阅读，原始数据按需切换。关系前后数值与增减合并为一张五轴图；Token 显示 K/M，并提供精确值与输入/输出占比。轮次默认最新在上，可切换排序。原生主题随 WebUI `1.1.1+chtholly.1` 补丁 wheel 安装；升级需同步源码并运行 `uv sync --locked --all-extras`，扩展页后端、`utils/webui_theme/` 与页面资源必须配套更新。原生主题修改通过 `scripts/build_patched_wheel.py --package webui` 重建，不直接修改第三方安装目录。

启用 `webui_config_apply` 后，已加载 LLM 的模型目录、全局及分模型凭证引用、接口地址、提示词与模型参数可通过原生“保存”直接热生效，不重启 Bot。正在执行的主聊天保持原模型直到本轮纠正与最终化结束，新轮次使用新配置；删除模型时同步修复默认选择，保留会话指针和历史。不显示常驻浮窗或独立重启菜单。

普通插件保存使用原生配置应用器，成功后立即更新运行摘要；失败保留候选配置及仍存活的旧插件，显示失败报告，不冒充运行一致。LLM 工具集合、WebUI、数据库、协议服务、基础配置及适配器等变更仍交给 Linux 控制器完整重启 Bot、健康验收和失败回滚，不重启 LLBot；未安装控制器时，此类变更在写入前拒绝。控制器通过既有密码会话读取状态，对精确候选的原生应用最多等待 90 秒，再完成五次连续健康检查，避免保存期间抢先重启；控制器和 systemd 单元须配套更新。模型热更新失败仍恢复原文件，无法确认恢复时明确报错。

控制器按 systemd 的停服期限等待，确认进程、控制任务及所属 cgroup 已结束后才继续启动；被 systemd 超时终止但已完全停止的服务仍可恢复。健康验收同时检查实际配置的必需插件，不能仅凭 WebUI HTTP 正常接受缺少 `llm_chat` 的运行状态。陪伴配置在写入前复用运行时限额校验，不再保存后才发现无法加载。

分模型的 `api_key`、`base_url` 留空或删除即可继承全局设置。凭证使用环境变量引用，不在表单中填写新密钥明文；新增或轮换进程环境变量仍需先重启使其进入运行环境。Bot 管理端口保持回环监听；可通过 SSH 隧道或下述独立 SSO 网关访问。

## 公网管理登录

公网入口使用独立 HTTPS 域名，经 Caddy 和 OAuth2 Proxy 接入 Casdoor OIDC。启用独立 `webui_sso` 后，Casdoor 认证会自动换取原生 WebUI 管理会话，不再输入第二次 WebUI 密码；SSH 隧道仍保留原密码登录。该 Casdoor 应用允许认证的账号均获得 WebUI 管理权限，不额外限制邮箱或组；网关使用签名 `sub` 作为身份，不要求账号填写或验证邮箱，但继续校验 issuer、audience、签名、nonce 和 PKCE。SSO 不写入 `llm_chat`，也不把后端切成全局免密模式。

部署配置位于 `scripts/webui.Caddyfile`、`scripts/webui-oauth2.cfg` 和 `scripts/chtholly-webui-oidc.service`。Caddy 的 `WEBUI_HOST` 指向管理域名，`ACME_EMAIL` 提供证书联系邮箱；该域名优先使用 Let's Encrypt，签发失败时使用 ZeroSSL 备用签发，不影响其他站点。Casdoor 应用回调须为该域名的 `/oauth2/callback`；OIDC client ID、secret、issuer、redirect URL 与随机 cookie secret 只保存在 root-owned `0600` 环境文件，通过 `OAUTH2_PROXY_*` 注入，不放到前端、Bot 配置或仓库。网关不可用时公网入口失败关闭，SSH 隧道仍可应急访问。

会话使用独立回环 Redis（`scripts/chtholly-webui-sessions.service`、`scripts/webui-redis.conf`）：刷新令牌只保留在加密的服务端会话中，浏览器仅持有签名票据。网关请求 `offline_access`，每 5 分钟按需刷新，Cookie 窗口为 12 小时；Casdoor 刷新令牌到期、撤销或账号权限失效时仍须重新登录。Redis 密码通过同一受限环境文件的 `OAUTH2_PROXY_REDIS_PASSWORD` 注入，ACL 仅保存密码哈希；默认 Redis 服务不启用，也不开放公网端口。旧 Cookie 会话切换到服务端存储时须重新登录一次。

Casdoor 应用的「授权类型」必须同时启用 `authorization_code` 和 `refresh_token`；只请求 `offline_access`、保存刷新令牌或设置刷新有效期都不能代替该配置。缺少 `refresh_token` 时，首次登录仍可能成功，但标准令牌端点会在后续刷新时返回 `unsupported_grant_type`，管理页随之无法续期。验收必须覆盖真实刷新，不能只检查登录成功或 `/ready`；不要改用 Casdoor 的独立刷新路由绕过应用授权类型检查。

在既有空前缀插件加载列表中加入 `webui_sso`，并设置它的 `public_origin` 为管理域名的 HTTPS origin；`auth_url` 默认固定指向 `http://127.0.0.1:4180/oauth2/auth`。插件只向该回环网关验证本轮请求的 SSO Cookie，然后复用原生 SessionStore；不接受伪造身份头，不修改第三方安装文件。退出先通过回环网关删除服务端会话，再清除两层 Cookie 并停在退出页，旧票据不可重放。后台标签页失效时不抢先打开登录页，回到前台后才重新访问当前管理页面，并优先复用其他标签页已续期的会话；浏览器返回缓存也会重新检查。登录流程的 CSRF Cookie 有效期为一小时；Casdoor 自身登录态不随此处退出连带清除。

连接恢复区分登录失效与临时网络故障：网关或身份服务不可用时返回 503，不删除会话、不重放写请求，也不自动发起登录。聊天与日志继续由原生 WebSocket 管理重连，HTTP 会话恢复会合并并退避；原生离线提示仍由真实健康检查控制。维护者通过 `scripts/build_oauth2_proxy.py` 构建固定源码与工具链的网关补丁，包含受限刷新超时、覆盖认证窗口的 Redis 锁租期与刷新令牌验证；构建默认执行回归并输出来源记录。

Caddy 只代理明确的管理页面、API 与两个管理 WebSocket；Satori/OneBot、自动 API 文档和未知路径一律拒绝。API、静态脚本和图标未认证时统一返回 401，不分别启动 OAuth 流程。跨站 Origin 和不带正确 Origin 的写请求在入口拒绝，管理内容禁用共享缓存。DNS 建议保持仅 DNS，以保留工坊最长 330 秒的请求窗口；如启用 CDN 代理，需另行确认超时与真实客户端 IP 配置。

## LLM 会话管理

`llm_chat` 按聊天范围保存会话、轮次、工具调用和确认交付，并按 Token 预算自动续接。登录 Entari WebUI 后，“LLM 会话”页面提供调用时间线、上下文注入、输入与输出三个视图；详细内容默认折叠，点击记录展开，支持全部折叠。生成期间自动刷新保留手动展开状态，较长内容按需分段加载与复制。

表情库、LLM 会话和提醒任务的 WebUI 入口支持原生热重载；旧页面卸载只清理自己登记的菜单和页面对象，不会误删刚替换的新版入口。扩展清单与实际页面路由需同时验收，数据接口仍正常不代表导航入口已经恢复。

历史工具记录会按当前工具声明检查；统计摘要、已脱敏引用和大段源码描述符仅作为历史信息提供，不冒充新调用的参数。已有会话无需清空或迁移，真实结果、失败状态和原文读取权限保持不变。

「输入与输出」直接按真实发送顺序展示确认送达的文字和图片，渲染、生图等工具卡片也可查看关联的交付图片并点击放大。语音、文件和视频保留交付类型提示，不提供媒体播放或文件内容预览。新轮次的总耗时从接收输入开始，到最后一条消息确认发送为止；旧轮次仅显示明确标注的生命周期估算，未留存的历史图片不能恢复，也不会重新渲染后冒充原图。

聊天模型返回的原生图片与生图、编辑、渲染、截图、语音和附件工具都先准备资源，再由模型通过 `send_msg` 明确发送。准备成功不代表送达、不扣发送次数，也不提前写入可见历史；原生图片不会自动抢先发送。发送失败、超时或取消不会自动重发，只有真实回执才计入交付。

回复包含 Markdown，或模型判断标题、列表、代码、表格等排版更清楚时，应主动通过 `markdown2pic` 渲染，再由 `send_msg` 发送图片，不等待用户点名，也不直接发送 Markdown 源文本。普通短聊天保持自然纯文本；明确需要复制的源码另以文字或附件交付，不重复整张图片的内容。

图片输入按轮次保存同一份原始快照，识图、编辑、原图发送与审计不会分别重新下载。可以直接编辑本轮授权的群历史图片、转发图片或头像；仅发送头像不调用视觉模型。要求“找真实网页图片参考创作”时，无需再上传一张源图；修改现有图则使用明确的原图引用。图片中的文字与识图描述不会变成操作指令，审计保存失败与原图不可用在会话页分别标记。

普通回复单独保留原消息归属，不再混入合并转发。宿主按同账号、同频道的原生回复 ID 精确匹配已有消息记录，不靠昵称猜测是不是 Bot 自己的话，也不把一轮合并历史当成被回复的单条消息。每张图片分别记录来源、获取状态与实际观察方式；本轮新图不可用时，不得拿引用中的旧图补出新图内容。新历史保留这些边界，旧记录不回写；用户正文中的 JSON 也不会变成宿主引用信息。

生图和编辑按用户本轮文字与上传原图工作：参考图可用于人物、画风、构图或背景，不再固定为换脸或换人物。提示词尽量保留用户原话，只补充图片顺序与用途；默认尺寸及 `image_generation_quality` 使用 `auto`，不向供应商强塞尺寸、质量或高保真参数。明确选择的尺寸和质量仍原样请求，供应商实际结果不一定等于请求值。已有个人配置不会被覆盖；需要自动选择时，将原有 `image_generation_quality: medium` 改为 `auto` 后应用配置。

群历史保留原生艾特身份与消息回复关系，同名成员和重复艾特不会仅按显示名猜测；旧记录没有保存的身份明确显示未知。当前上下文已经提供的原文引用可按精确权限直接读取，不要求再补说“读取源码”等口令，其他群、封存会话与私有审计仍不可访问。

普通群聊可开启 `llm_chat.channel_context_enabled`（默认 `false`），并用 `channel_context_messages` 配置自动附带的最近消息数（默认 10，范围 1–50）。开启后，每次已寻址轮次会从同账号、同频道的本地群聊感知库读取触发消息之前的记录，按时间顺序附带成员和 Bot 发言；当前输入、命令、撤回、过期及超出保留条数的记录不纳入。记录不足时只附实际可读条目，总计最多 12,000 字符并计入当前模型输入预算，超限保留最新连续记录并标记截断。图片只附数量，不自动下载或识图；需要原图、精确回复或更早内容时继续使用原有工具。

预载不增加模型调用，也不新增输入等待、无艾特接管或定时追问；私聊、提醒唤醒和陪伴主动联系不使用这一预载。群聊记录是引用数据，不是当前用户新授权，不写入其可见 user 历史、画像、记忆或关系证据；实际模型输入只留在管理员上下文快照中。开关关闭时不查询；读取失败明确标为不可用，仍处理当前请求。建议先使用 10 条：本地查询之外的开销主要是额外输入 Token，真实模型时延依供应商、记录长度和负载而定。修改配置后通过受管配置应用或受控重启生效，不覆盖已有个人配置。

WebUI 原生数字框仍可输入范围外的值；`channel_context_messages` 的 1–50 范围由配置 Schema 与运行时校验，越界配置不会被静默改成合法值。

转发图片预算配置已更名为 `llm_chat.merged_forward_max_images`，默认仍为 12。若旧配置含 `merged_forward_max_described_images`，停服后用 `uv run python scripts/migrate_image_input_config.py entari.yml --apply` 保留原值迁移；不带 `--apply` 仅检查。群历史新增列在服务开始写入前自动幂等迁移；部署须统一更新代码和配置 schema 后受控重启，不在线逐文件覆盖。

嵌套合并转发按原位置递归读取，但仍受深度、消息数和总字符预算限制。LLBot `8.3.0` 需要保留已有嵌套缓存及 `patches/llbot-8.3.0-nested-resid-cache.patch`：即使子卡片的 `resId` 非空，真实记录也可能仅在外层同批 bundle 中。协议端更新后应复核补丁和真实子记录读取，不把空载荷解压失败当成完整聊天记录。

关系与情绪按成员持续保存，普通对话不再套用固定回应档位：模型可以自然聊天、只发表情、明确拒绝或主动沉默。后台评估合并完整的未处理互动，失败保留证据；短期情绪随时间回落，不每天清空长期关系。`relationship_eval_batch_size`（默认 8）是单批上限，`relationship_eval_debounce_seconds`（默认 2 秒）是合并窗口，不是每隔若干条只评最后一次。

模型通过有序 `segments` 自主组合文字、艾特、图片、链接和表情：同一条消息可以先说话、在中间艾特，再插图或继续文字；运行时不加空格、不把艾特挪到开头、不强制图片先发。每次 `send_msg` 对应一条原生消息，不代表一轮只能发一条；普通聊天的独立反应、建议和后续打算必须分次调用，自然形成不同气泡。多段普通正文不能用换行、多个文字段或样式塞进同一条；发送前会拒绝并交回模型纠正，不偷偷拆条或压平换行。短答及属于同一反应的文字加图片仍可同条，代码、列表、表格、引用和有标题的结构化说明保留排版。当前 OneBot 无法保持单条的语音、视频、文件及合并转发组合仍在发送前明确拒绝。

普通正文中的字面量 `\n` 或 `\r\n` 同样会在发送和额度预留前被拒绝，代码、正则和可识别路径保持原样。尚未发送的非法最终文本只允许一次保留工具能力的纠正，沿用已完成的工具结果和已准备媒体，由模型分次发送；重复非法候选不交付。一旦已有确认输出，后续普通最终文本仍丢弃，避免重复。结果未知后停止本轮后续发送，不因分条或纠错重放消息。

普通模式下，多人同时提问时模型处理仍并行，只有已经准备好的回复进入群级发送调度；每组最多连续 3 条，满 4 秒后让位给其他就绪轮次，不强制中断已开始的传输；后续内容尚未准备好就让其他人先回复。同一轮未被打断时只在首条引用原问题，后续直接发送；等待模型、间隔较长或达到公平轮转边界不会让每条都重复引用。切换到其他轮次，或被同频道其他消息打断后恢复，才再次引用，不额外艾特。文字和图片直接使用原生引用；语音、文件、视频和合并转发受 OneBot 能力限制，直接发送原载荷，不为引用归属额外补发文字。若本来还有必要的文字或图片，再在该条真实内容上引用原问题。发送超时或取消不会盲目重发。

同一成员在 Bot 处理期间继续按原方式寻址、补充要求或发图，会有序加入当前任务，不再取消旧任务重来，也不刻意等待几秒收齐消息。模型在安全节点看到原问题、已完成的工具结果及补充内容；后面的纠正生效，前面不冲突的要求继续保留。已完成的搜索、写入和确认发送不会因补充而重做，尚未发送的旧内容可被新要求阻止；补图可以继续识图、编辑或发送。不同成员互不抢占；任务已完成或接纳满 64 条输入后，后续消息按序进入下一任务。普通群消息仍须满足原有寻址规则，不新增无艾特接续。

会话页保留原问题并逐条标记补充输入，分别显示真实接收、应用时间及未接纳原因，不伪造旧任务取消。生成时的关系与情绪、实际回应方式、评估前后变化和关联证据仍可查看；同一逻辑任务只形成一次完整互动证据。合并评估明确标注贡献轮次，失败与等待不显示成零变化；自动刷新保留展开状态、焦点与滚动位置，评估完成后停止轮询。

会话页通过原生 WebUI 的已认证父页面读取 API 和图片附件，兼容隔离 iframe 与密码登录；源码脚本和样式以内联 nonce 加载。切换轮次会停止旧的分页读取并释放临时图片地址，不关闭认证，也不放宽 iframe 的同源隔离。

在 `llm_chat.personas` 下按角色键配置 `name`、`prompt`、`appearance` 和可选的 `reference_image`，用 `default_persona` 指定默认角色。人格和口吻由所填 `prompt` 定义，不额外附加情景对白或固定说话示例；参考图使用 `resources/image` 下已有文件的安全相对路径。角色相关生图或编辑会将选用的参考图原始字节直接交给独立图像模型，不经过聊天模型描述，也不依赖聊天模型是否支持视觉；无关主体不会附带角色图，指定参考不可用时明确失败，不退回文字重构。旧 `persona` 移至对应角色的 `prompt`，旧 `self_reference_image` 移至该角色的 `reference_image`。

TTS 默认声音失效时仍能列出真实可用声音，并明确报告默认配置问题；完整指定另一个有效选项可以合成，显式点名不存在的声音仍会被拒绝，不自动替换。

仓库配置保留 `chtholly` 为默认角色，并提供按 [PRTS 佩佩资料](https://prts.wiki/w/%E4%BD%A9%E4%BD%A9)、语音及相关剧情整理的 `pepe`，参考图为 `persona/Pepe.png`（原版初始立绘）。超管可用 `llmchat persona pepe` 切换当前聊天范围。

普通成员可查看当前角色列表、会话与 Token 信息：

```text
llmchat persona
llmchat session
```

Token 信息区分供应商实际用量与上下文估算；缺失数据明确标为未知。历史注入快照保留当轮记录，不会随当前人格配置变化；修改人格后请查看新轮次。凭证、图片像素及内部思考不进入新增调用快照。

超管可显式控制当前群会话：

```text
llmchat persona chtholly
llmchat new
llmchat reset
llmchat handoff
```

`persona <key>` 只切换当前聊天范围，并创建不继承旧话题的会话；已有轮次和后台评估继续使用各自启动时的人格快照。`new` 保留关系、画像和长期记忆，但不继承上一话题；`reset` 封存旧会话并新建，不删除审计事件；`handoff` 携带结构化交接继续当前任务。以上变更指令仅限超管，关系与长期记忆不会因换角色清空。

### 自主陪伴对话模式

默认使用普通对话。任何成员可只读查询当前模式；仅当前配置的超管可在群聊或私聊中切换，模型工具不能代替管理员启用：

```text
/llmchat mode
/llmchat mode companion
/llmchat mode normal
```

模式按账号与对话范围持久化，不影响其他群或私聊。开启陪伴后，群聊会接收真实的非指令消息，不再要求每条都艾特 Bot；同一频道只有一个前台对话，连续消息短暂合并，艾特或回复优先接入。生成期间的新消息在安全边界补入，已经开始的工具或发送不会被打断重放。普通模式仍保留原来的寻址入口和成员间并行。

模型可以参与、暂时旁观、约定一次后续检查，或结束当前交流；旁观不会在无人说话时反复调用模型。群聊与私聊使用不同交流策略，但继续使用现有聊天模型，不新增分场景模型配置。每位真实参与者的画像、关系、情绪、记忆和评估证据独立归属；引用内容、旁观消息和其他成员身份不会授予写入权限。

陪伴群聊可以在同一轮分别回复不同成员：每条发送独立选择要引用的真实消息，以及是否艾特该消息的作者；不再把所有回复自动挂到最先触发的群友名下。不指定引用时就是面向群内的普通消息。模型上下文按每条输入绑定作者及个人资料，不把根消息作者当成整段群聊唯一的“当前说话人”；同名、改名和连续补充也保持独立归属。回复目标不改变频道、超管权限或成员写入授权。

角色的虚拟活动、兴趣与计划仍由独立复盘维护。复盘提出的话题进入同一前台对话，而不是由另一个发送器插话；群级开场不伪造真人作者，已确认的主动发言可以被后续陪伴聊天看见。内部复盘仍是私有记录，虚拟日常不能冒充真实购买、出行或工具成果。

陪伴不是固定问候定时器，也不以待办任务为触发条件。一个话题聊完后，角色仍可主动分享自己的想法、延续共同话题或跟进真实关切，无需成员再给任务或补操作口令；成员希望自然主动联系的偏好，不会因一次早安被视为永久完成。是否开口仍由模型结合人格、关系和当时事实决定，不强制每次复盘都发消息。当前具有 `reminder` 权限的普通对话，可以搭配提醒安排固定复盘之外的具体主动对话，不要求额外口令；尊重成员时间与联系偏好，只有提醒确认持久化后才可声称已安排。这不扩大主动联系执行轮次的工具权限。

`normal` 立即取消该范围的自主工作，保留已有状态，并且不再新增本机制的后台模型请求；普通聊天、关系评估和明确委托的提醒保持各自原有语义。重新启用只安排新的判断，不补发停用期间的积压。真实回执才表示送达，未知结果不自动重发；无人回应不会额外延长主动联系间隔，也不会伪造负面关系反馈。本人仍可通过 `llmchat reminder off` 关闭对自己的自主联系，不影响明确委托提醒。

`companion_*` 配置继续控制内部复盘模型、输入输出预算、复盘及联系上限；前台对话仍使用原有 `model`。`companion_contact_interval_minutes` 是主动联系之间的固定短时防重复间隔，不限制正在进行的真人交流，未回复不会触发额外退避。`companion_daily_contacts` 默认每日 24 次，仅作防失控兜底，不是发送目标：成员联系按成员与范围计数，群级主动开场按范围单独计数。管理员可设为任意非负整数，例如 96；设为 0 只停止主动联系。内部复盘频率和模型预算独立，不会因提高联系上限强制增加请求。完整默认值见 `entari.full.example.yml`；停止该机制的后台开销请切回 `normal`。

普通聊天仍在进行时，服务先等待本轮结束，不为立即中断的内部复盘占用每日模型额度。完成聊天继续保存证据，但不提前既有未来复盘；已到期的复盘至少等待本次聊天结束五分钟，已排到次日的预算恢复也不会被拉回当天。历史对话携带真实时间，临时停聊按时间与范围解释，用户明确的持续禁扰仍有效。发送前的安静时段、活动窗口、联系间隔、偏好和额度检查不变；已开始或结果未知的模型请求不因取消而补回额度。

在 WebUI 的 **LLM 会话 → 陪伴视图** 中，按频道查看当前模式、下次复盘、运行限额、虚拟日常、成员关切与联系偏好，并按人格、状态分页检查每次复盘。详情分开显示实际输入、结构化复盘结论与联系提案、宿主放行或拦截、状态提交及真实联系结果；可跳转到对应模型轮次、发送记录和已核验的原始聊天证据。模型、Token 和耗时沿用实际审计，未知发送结果不当作未发送，旧记录缺失不以当前配置或状态补造。虚拟日常明确标为虚构，结论不是隐藏思维链。

会话检查支持普通聊天、提醒、主动联系和内部复盘四种用途，默认显示普通聊天；独立的 **回应决定** 页签展示当时模式、触发来源、模型的结构化回应理由与真实输出。内部会话仅供检查，不能通过新会话或续接按钮改变调度生命周期。陪伴面板只读，不调用模型、不修改模式或补发消息；可见时有界更新活动记录，并在已记录的下次复盘时间读取新记录，隐藏或离开页面后停止。刷新保留筛选、选择、展开、焦点和滚动位置；窄屏及侧栏挤压后的中等窗口分别查看概览、复盘列表和详情，避免三栏横向溢出。

新增复盘的 `decision_summary` 与宿主 `companion_contact_decision` 只进入管理员审计，不进入模型历史、handoff、画像或长期记忆；审计与管理页面不增加新的联系权限或改变安静时段、间隔、额度及未知结果不重发的策略。部署时应同时更新陪伴运行代码、管理投影、完整页面资源及 `scripts/webui.Caddyfile` 中三个精确只读路由，不能只覆盖 CSS 或公开整个 API。


### 持久提醒


普通成员可以让模型通过 `reminder` 工具创建一次性或自适应提醒。需要未来联系、提醒或继续任务时，模型根据当前对话判断是否以及何时安排新的模型轮次，不依赖固定口令，也不把每句未来闲聊机械变成任务。用户给定的时间应保留，依据不足时澄清；工具确认保存后才可声称已经安排。模型只能保存有界目标、显式带时区的 ISO-8601 时间，私聊投递必须由当前用户明确授权。每个任务保有独立的提醒会话；每次唤醒还从交付账号与频道正在生效的普通聊天会话中，选取近期已完成的对话作为只读、限额且脱敏的上下文。来源群的消息不会跨到私聊，已封存的会话、未完成轮次和历史工具权限也不会随之迁移；普通聊天会话不写入伪用户消息或提醒执行轮次。唤醒时记录本次实际选中的普通聊天与提醒历史轮次，旧记录未捕获的上下文不能事后用当前配置补造。模型在任务执行后通过 `reminder` 的 `resolve` 动作确认完成、继续或暂停。决议在本轮原生工具子任务与调度服务之间共享，最终状态以宿主事务结算为准；只有真实协议回执才计为已发送。已发送但缺少有效结束决议时任务保持暂停，不会自动重复发送，发送结果未知时也不会自动重试。

提醒服务启动遇到 SQLite 临时锁时会释放失败事务，按 1、2、4、8、10 秒间隔持续等待后恢复；卸载或取消会停止等待。其他初始化错误明确记录为启动失败，不假装提醒已就绪。恢复只领取仍有效且未执行的任务，保留原计划时间；已确认送达、结果未知或历史暂停任务不会因此重新发送。

本人可用以下指令查询和控制自己的提醒。任务编号是提醒工具返回的不透明引用，暂停、恢复和取消都按当前版本号执行，状态变化冲突时不会重放操作：

```text
llmchat reminder list
llmchat reminder pause <task_ref>
llmchat reminder resume <task_ref>
llmchat reminder cancel <task_ref>
llmchat reminder off
llmchat reminder on
```

`off` 只关闭未来的自主联系，不自动恢复已暂停任务；明确委托的提醒保持原状态。已登录的 WebUI 管理员可在“提醒任务”页按来源频道、创建时的普通会话、状态及目标或用户筛选全部任务（包括未归属与未关联来源会话的任务）；任务详情分开呈现创建来源、当前任务状态、历次唤醒的执行环境、实际注入上下文、调用与确认交付。管理员可修改目标、背景、延续状态和下一次带时区的时间，或暂停、恢复、取消。修改以当前任务修订号提交，冲突时须刷新；已发送或结果未知且原定时间已过的任务只能先改到未来时间再恢复，避免重复投递。该页面不接受浏览器传入的聊天用户身份，免密模式不授予管理权。

网页截图由模型判断是否对当前任务有用：网页布局、图表或可见区段需要像素时可以截取，正文已经足够时优先读取文字。无需补说“截图”口令；找原图、照片或素材仍应使用原始图片而非网页截图，公开 URL、SSRF 和网页调用额度保持不变。

表情收藏与标注不再提供聊天指令；人工管理统一使用 WebUI“表情库管理”。页面的脚本与样式以内联 nonce 加载，列表、图片、上传与修改都通过已认证父页面的 API bridge 工作，兼容隔离 iframe。图片使用受限 Blob URL，翻页或关闭时释放；上传保留原始 multipart 边界，不开放匿名文件接口或放宽沙箱。模型按需收藏与启动增量标注仍保留。

人格作息按上海时区计算；低精力会让文字回复简短，但不会减少明确请求的媒体交付额度（默认每轮最多 6 条）。静态报告继续使用图片渲染，网页与交互原型使用下面的作品交付流程。

## 网页作品与源码

直接描述任务即可，例如“帮我设计并优化一版ui”；无需特定关键词、空格或额外的发布、读取、打包口令。模型按任务自主选择生成预览、查阅已有作品及准备源码。启用作品服务后，Bot 保存完整 HTML、CSS、JavaScript 与同包素材，并准备交互预览链接、预览图和原始源码 ZIP，再由 `send_msg` 显式发送；源码不再用代码图片代替。协议不支持的消息组合在发送前报错，不自动拆条或把文件悄悄替换成链接。

每次修改产生独立版本，支持查找、读取、修改当前聊天范围内自己的作品；撤销链接仍需要当前用户明确提出。链接默认有效 24 小时；持有链接的人都可以预览和下载，过期或撤销后页面、素材和 ZIP 同时失效。不要在作品中放入密钥、真实登录信息或私人对话。

模型可以先读取精确作品版本的完整文件清单，再分页读取某个源文件，包括没有被入口页面引用的辅助文件；清单、源码和下载 ZIP 来自同一不可变版本，过期、撤销和权限限制保持一致。

预览仅支持静态前端交互，不运行服务端代码、不安装项目依赖，也不连接真实支付、登录或 Bot API。作品的截图与源码文件先于说明文字发送，并计入同一轮媒体额度。

配置 `llm_chat.web_artifacts_public_url` 为独立 HTTPS 域名后启用；留空则不注册作品工具。`web_artifacts_capture_url` 必须指向回环截图接口，`web_artifacts_capture_token` 通过环境变量注入，`web_artifacts_ttl_hours` 控制有效期（最多 168 小时）。独立服务与仅公开作品路由的代理示例位于 `scripts/chtholly-web-artifacts.service` 和 `scripts/web-artifacts.Caddyfile`；管理面板端口不得对公网开放。

Bot 与独立预览进程共享项目依赖环境；同步依赖或浏览器后，必须同时重启 `chtholly.service` 与 `chtholly-web-artifacts.service`。仅健康接口成功不能证明截图可用，需用一次真实作品验证隔离截图返回 PNG；不要关闭 Chromium sandbox 或网络隔离来绕过失败。

## 插件工坊

启用 `plugin_workshop` 与 `llm_chat.plugin_workshop_enabled` 后，只有配置中的 **superuser** 能让模型使用工坊工具。流程分为两步：`submit_plugin` 保存完整源码、命令、配置、权限与数据声明，并在无生产凭证及数据的 Linux Docker 容器中验收；模型读取反馈、修订源码，验收通过后再调用 `activate_plugin` 激活精确版本与 SHA-256。无需通过指令或 WebUI 人工批准，也不要求补充“提交”“批准”“激活”等口令。提交和验收通过本身不会激活插件。

`list_workshop_plugins` 与 `read_workshop_plugin` 同样只对当前 superuser 开放，读取限当前会话范围；模型可找回完整 manifest、文件清单、源码及失败报告后修订，不从摘要猜文件。`rollback_plugin` 只能恢复曾经成功激活且验收有效的精确版本；`disable_plugin` 停用插件并保留版本和数据。普通成员、定时提醒、自主陪伴、过期 generation 与 WebUI 管理会话均不能借用工坊写权限。

验收宿主需 Linux 与可用的 Linux Docker Engine；Windows 可在 WSL2 的 Linux 环境运行宿主。维护者需显式构建与当前锁文件一致的验收镜像：

```shell
uv run --locked python scripts/build_workshop_sandbox.py --tag chtholly-workshop:local
```

构建只打包固定依赖、vendored wheel 和可信验收器，不发送项目配置、资源或 `.env`；模型提交不会构建或拉取镜像。镜像预装 Chromium、Inter/Noto CJK 字体和图像解码器，先验证可信模板的真实 PNG，再执行候选命令、重载及清理。模板访问限于候选源码目录，单命令 30 秒、总验收默认 180 秒；图片须完整解码并满足大小、像素和动画限制。Docker、镜像或版本前提不满足时明确显示不可用，不回退到宿主验收。

容器验收与激活后的宿主渲染使用各自的 HTMLRender 配置。宿主 `htmlrender.resources.local_access.allowed_paths` 必须同时保留原有模板目录和工坊专用 `runtime` 目录；本仓库默认 `.localdata.app_name: chtholly` 对应 `.chtholly/data/plugin_workshop/runtime`，改变 LocalData 位置时需同步调整。该目录只发布经 superuser 工具选择、验收通过且哈希匹配的源码，停用时删除对应包；不得授权整个 `.chtholly`、`versions` 或 `staging`。激活不会自动扩大渲染器文件访问权限，验收需同时覆盖激活后的实际命令出图。

生产推荐由 Bot 用户运行 rootless Docker，并通过 `DOCKER_HOST` 指向受限 Unix Socket；不要为方便调用而将 Bot 加入可控制宿主 root 的 Docker 组。rootless daemon 必须支持 cgroup v2 的内存、CPU 与 PID 限制，不能因安装模式改变而放宽验收边界。

Entari WebUI「插件工坊」仅供查看源码、版本差异、不可变配置、数据声明、验收报告与 SHA-256，不再提供提交、重新验收、批准、激活、回滚或停用入口；旧写 API 不保留兼容路径。工坊仍要求预先配置 WebUI 密码，在回环监听时同样启用真实认证；已有免密会话时需完整重启使旧 Cookie 失效。管理端口保持回环监听及 SSH 隧道。页面复用原生隔离 iframe 的 API 消息桥，不放宽 sandbox 或会话认证。

超管只读查询命令保留：

```text
workshop help
workshop list
workshop show counter_demo 1
```

失败更新保留并尽力恢复旧版；重启只恢复已提交且启用的版本，不会自动激活仅通过验收的候选。旧数据库中的历史审批列保留原值，但不再参与授权，也不补造批准记录。源码、版本及操作日志继续由 LocalData 管理；配置或源码变化仍需新版本与重新验收。

**superuser 的工具调用是原生执行的信任边界，验收不是安全认证。** 激活后插件拥有 Bot 进程的全部权限，权限清单只是声明；验收器与候选同进程，功能报告可能被恶意代码伪造。代码回滚与停用不会撤回消息、外部请求或数据修改。不要把 Docker Socket、宿主凭证或生产数据挂入验收容器。容器无直接网络出口，仅可经受限 Unix Socket 代理调用 Open-Meteo 的地名和天气 GET 接口。
